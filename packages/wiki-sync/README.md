# @plane/wiki-sync

`plane-wiki-sync` exports the published pages of a Plane workspace **Wiki** into a
[Docusaurus 3](https://docusaurus.io) docs instance: one CommonMark `.md` file per page, a folder
with `index.md` + `_category_.json` for every page with children, and the page images downloaded
into `static/`. It runs before `docusaurus build`, typically in GitHub Actions on a schedule.

```
Plane  --X-Api-Key-->  /api/v1/workspaces/<slug>/wiki/pages/        (cursor walk)
                       /api/v1/workspaces/<slug>/wiki/pages/<id>/   (changed pages only)
                       /api/v1/workspaces/<slug>/assets/<id>/       (presigned image URL)
       ---> wiki/**.md + _category_.json, static/wiki-assets/<asset id>.<ext>, .wiki-cache/manifest.json
```

## Install (in the Docusaurus repository)

The package is not published to npm. Its `dist/` is a self-contained bundle with no runtime
dependencies, so install a packed tarball:

```bash
# in the Plane repository, at the release tag
git checkout wiki-sync-v0.1.0
pnpm install && pnpm --filter=@plane/wiki-sync build
cd packages/wiki-sync && pnpm pack          # -> plane-wiki-sync-0.1.0.tgz
```

Attach the tarball to the GitHub release of that tag, then in the Docusaurus repository:

```bash
npm install --save-dev https://github.com/<org>/<plane-fork>/releases/download/wiki-sync-v0.1.0/plane-wiki-sync-0.1.0.tgz
```

(Committing the `.tgz` to the docs repo and installing it with `npm install --save-dev ./vendor/plane-wiki-sync-0.1.0.tgz` works too.)

Requires Node.js 20 or newer.

## Docusaurus setup

Copy the files from `node_modules/@plane/wiki-sync/templates/`:

| Template                    | Goes to                 | Purpose                                                                                                                                                                                                                                               |
| --------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `docusaurus.config.wiki.ts` | site root               | `markdown.format: 'detect'`, `onBrokenMarkdownImages: 'throw'`, a second `plugin-content-docs` instance (`id: 'wiki'`, `path: 'wiki'`, `routeBasePath: 'wiki'`, `numberPrefixParser: false`) and a navbar item; import it from `docusaurus.config.ts` |
| `sidebars-wiki.ts`          | site root               | autogenerated sidebar built from the folder tree                                                                                                                                                                                                      |
| `wiki.css`                  | `src/css/wiki.css`      | callout (`--callouts html`), task list and table styles; add to `theme.customCss`                                                                                                                                                                     |
| `smoke-fixture.md`          | `wiki/smoke-fixture.md` | hand-written page with everything MDX would reject; keeps CI honest across Docusaurus upgrades                                                                                                                                                        |
| `wiki-sync.yml`             | `.github/workflows/`    | cron every 6 hours + manual + `repository_dispatch` (`plane-wiki-updated`); sync, build, deploy to GitHub Pages; skips the build when nothing changed                                                                                                 |

Pin `@docusaurus/core` (and the preset) to `3.10.x`: CommonMark mode is documented as experimental.

`package.json` scripts:

```json
{
  "scripts": {
    "sync:wiki": "plane-wiki-sync",
    "build": "docusaurus build"
  }
}
```

`.gitignore` (the wiki is regenerated on every CI run; keep the hand-written smoke page):

```gitignore
.wiki-cache/
static/wiki-assets/
wiki/*
!wiki/smoke-fixture.md
```

## Configuration

Environment:

| Variable               | Example                     |                                                       |
| ---------------------- | --------------------------- | ----------------------------------------------------- |
| `PLANE_URL`            | `https://plane.example.com` | Plane base URL (also used for "Edit this page" links) |
| `PLANE_WORKSPACE_SLUG` | `acme`                      | workspace slug                                        |
| `PLANE_API_KEY`        | `plane_api_...`             | API token, sent as `X-Api-Key`                        |

Only pages that are **published to the docs site** are exported: open the page in Plane and choose
**Publish to docs site** in its actions menu (workspace admins and members; the header then shows a
globe icon). Only public, non-archived pages can be published, and making a page private, archiving
or deleting it unpublishes it. **Unpublish from docs site** removes it from the next export.

Create the token for a dedicated bot user that is a workspace **guest**: the export endpoint only
returns published, public, non-archived wiki pages anyway, and a guest token cannot change anything. Store it
as the `PLANE_API_KEY` repository secret; `PLANE_URL` and `PLANE_WORKSPACE_SLUG` as repository
variables.

Flags:

```
--out <dir>            Docs instance folder                 (default: wiki)
--assets <dir>         Folder for downloaded images         (default: static/wiki-assets)
--public-path <path>   URL of the assets folder on the site (default: /wiki-assets)
--route-base <path>    routeBasePath of the docs instance   (default: /wiki)
--cache <file>         Manifest used for incremental runs   (default: .wiki-cache/manifest.json)
--concurrency <n>      Parallel API requests                (default: 5)
--callouts <mode>      admonition | html                    (default: admonition)
--projects-dir <name>  Folder for project wiki sections     (default: projects)
--projects-label <txt> Sidebar label of that folder         (default: Projects)
--force                Re-render every page, ignoring the manifest
--from-fixture <file>  Read pages from a JSON fixture instead of the API
```

The API is rate limited (60 requests/minute per token by default). 429 responses are retried after
`X-RateLimit-Reset` (or `Retry-After`); unchanged pages are skipped using the manifest, so a
scheduled run usually costs one list request plus one request per edited page.

## Output

| Plane                             | Docusaurus                                                                                     |
| --------------------------------- | ---------------------------------------------------------------------------------------------- |
| page without children             | `wiki/<path>.md`                                                                               |
| page with children                | `wiki/<path>/index.md` + `wiki/<path>/_category_.json` (`link` to that doc, `collapsed: true`) |
| `id`                              | front matter `id` (stable across renames); doc id = folder + uuid                              |
| `name`                            | `title`, `sidebar_label`; slug from the name, de-duplicated among siblings (`faq`, `faq-2`)    |
| `sort_order`                      | `sidebar_position` / category `position`                                                       |
| `description_stripped`            | `description` (160 chars)                                                                      |
| `updated_at`                      | `last_update.date`                                                                             |
| page URL in Plane                 | `custom_edit_url`                                                                              |
| parent not exported (unpublished) | page moves to the root                                                                         |

### Project wiki sections

Plane marks the root wiki page of each project with `project_wiki: {project_id, identifier, name}`
(always a top-level page; `null` or absent on every other page, and on older Plane versions). Such
a page and everything below it are exported under the projects folder instead of the wiki root:

```
wiki/
  getting-started.md                 ordinary pages stay at the root
  engineering/...
  projects/
    _category_.json                  {"label": "Projects", "position": 1000000000, "collapsed": false}
    web/                             project root page, slug = lowercased identifier ("WEB")
      _category_.json                {"label": "<project name>", "link": {"type": "doc", ...}, ...}
      index.md                       the project root page
      architecture/index.md ...      its sub-pages, nested as usual
    mob/                             an empty project root is still a folder (stable URL)
      _category_.json
      index.md
```

- The folder name and label come from `--projects-dir` (one folder name) and `--projects-label`;
  the folder is placed after every top-level page and is only written while at least one project
  section exists.
- Identifier slugs are de-duplicated like sibling slugs (`web`, `web-2`). While sections exist, an
  ordinary top-level page whose slug would be the projects folder gets a suffix (`projects-2`).
- Links to pages inside a section point at `/wiki/projects/<identifier>/...`; renaming a project
  identifier or linking/unlinking a section changes the link map, so every page is re-rendered and
  the old files are removed (see below).

Every file has `format: md`, so it is parsed as CommonMark (never MDX) even if the site's
`markdown.format` changes; Docusaurus adds `rehype-raw` for `.md` files so the raw-HTML fallbacks
below render.

Content mapping:

| TipTap node                                                                                                | Markdown                                                                                                                                                                                                         |
| ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| headings, paragraphs, bold/italic/strike, inline code, links, lists, blockquotes, code blocks, hard breaks | CommonMark/GFM; text is escaped (`<div>` typed in a page stays text)                                                                                                                                             |
| underline, text/background colour, alignment                                                               | dropped (text kept)                                                                                                                                                                                              |
| task list (nested)                                                                                         | GFM `- [ ]` / `- [x]`                                                                                                                                                                                            |
| table without merged cells, one paragraph per cell                                                         | GFM table                                                                                                                                                                                                        |
| other tables                                                                                               | raw `<table>` (colspan/rowspan and valid background colours kept)                                                                                                                                                |
| image (`<image-component>`)                                                                                | downloaded to `static/wiki-assets/<id>.<ext>`, emitted as `![name](/wiki-assets/<id>.<ext>)` (processed by webpack, so `baseUrl` is honoured); width is not kept                                                 |
| Excalidraw drawing (`<excalidraw-component>`)                                                              | its PNG asset, downloaded and emitted like an image: `![name or "Drawing"](/wiki-assets/<id>.png)`; a drawing whose asset is missing is dropped                                                                  |
| callout                                                                                                    | `:::note/tip/warning/danger/info[emoji]` (gray/purple: note, green: tip, peach/orange: warning, pink: danger, blue: info); `--callouts html` emits `<div class="plane-callout plane-callout--<colour>">` instead |
| user mention                                                                                               | `@display_name` when the token may list members, otherwise `@member`                                                                                                                                             |
| work-item embed                                                                                            | removed                                                                                                                                                                                                          |
| divider                                                                                                    | `---`                                                                                                                                                                                                            |
| links to wiki pages (`/<ws>/wiki/<id>`, `/<ws>/projects/<p>/pages/<id>`)                                   | `/wiki/<path>`; links to pages that are not exported point at Plane                                                                                                                                              |

## Incremental runs and cleanup

`.wiki-cache/manifest.json` records, per page, the file it wrote, `updated_at` and the images it
uses. A page is fetched again only when `updated_at` or its path changed (or with `--force`); a
rename that changes any page's URL re-renders every page so links stay correct. Files and images
that a previous run wrote but the current run did not are deleted, together with folders left
empty (including `projects/` when the last section is unlinked). Files never written by the tool (for example `wiki/smoke-fixture.md`) are not touched.
Cache `.wiki-cache`, `wiki` and `static/wiki-assets` between CI runs (the workflow template does)
to benefit from this.

## Development

```bash
pnpm --filter=@plane/wiki-sync build
pnpm --filter=@plane/wiki-sync test
node packages/wiki-sync/dist/cli.js --from-fixture packages/wiki-sync/tests/fixtures/wiki-fixture.json --out /tmp/wiki
```

`src/vendor/markdown-parser` is a copy of `packages/utils/src/editor/markdown-parser` (bundling
`@plane/utils` would pull React into the CLI); `tests/vendor-parity.test.ts` fails when upstream
changes.
